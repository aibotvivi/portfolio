AI features don't fail loudly.

Something I learned running my own software, which I now can't unsee at work.

I keep a small news dashboard that assembles itself at eight every morning. It reads a dozen feeds, writes a bilingual front page and leaves it on a local server before I've made coffee. For weeks it was the least interesting thing I own.

Then for several mornings it stopped working, and I didn't notice.

Not because it broke — because it didn't. Each morning the job started, spent somewhere between three and seventeen hours going round in circles, and died. Nothing crashed on my screen. The page wasn't empty: yesterday's front page was still sitting there, looking exactly like a page that had just been built. The failure and the success were visually identical.

The fix wasn't a better prompt. It was a hard timeout, a lock so two runs can't overlap, and a dead-man's switch — something that expects a ping every morning and complains when one doesn't arrive. You cannot find an event that didn't happen by reading the log of events that did.

I think about this constantly now, because it is the shape of most AI failure inside a product, and it is a design problem before it is an engineering one.

A model that returns nothing looks like a quiet day. A model that returns something plausible and wrong looks like a feature working perfectly. Neither throws the red state we spent a decade learning to design — the error toast, the retry, the something went wrong. Our whole vocabulary for failure assumes failure announces itself. These ones don't.

In payments, and in trust and safety, that distinction isn't academic. A check that visibly breaks gets fixed on Tuesday. A check that quietly stops running gets found in an audit.

So these are the questions I now ask in the same breath as “what does this feature do”:

  • What does it look like when this returns nothing? Not an error — nothing.
  • How does a person tell a confident answer from a correct one?
  • Who finds out, and how, if it quietly stops?
  • What is the honest thing to show while we don't know yet?

None of those are answerable in Figma, which is the real reason I build the things I design. A prototype that cannot fail can't show you what failing looks like — and with an AI feature, what failing looks like is the design.

Written September 2026. The dashboard it came from is in The Lab, timeout and all.
